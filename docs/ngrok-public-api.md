# Публичный API через ngrok: защита от ботов

## Что защищено

API ограничивает запросы по реальному IP клиента: по умолчанию 120 запросов в минуту
на весь API и 60 в минуту на каталог/поиск. Создание аккаунта, вход, публикация,
жалобы и раскрытие контактов имеют отдельные более строгие лимиты. При превышении
сервер возвращает `429 Too Many Requests` и `Retry-After`.

Не отключайте `TRUSTED_PROXY_NETWORKS=172.16.0.0/12` при запуске API в Docker.
ngrok подключается к опубликованному порту хоста, Docker передаёт этот запрос в
контейнер, а приложение доверяет только этой внутренней сети для `X-Forwarded-For`.
Так лимит считается по IP посетителя, а не по IP туннеля.

## Запуск

1. В `.env` задайте `ASPNETCORE_ENVIRONMENT=Production` и укажите точный адрес
   фронтенда в `CORS_ALLOWED_ORIGINS`. Нельзя использовать `*`.
2. Запустите API: `docker compose up -d --build`.
3. В панели ngrok скопируйте автоматически назначенный development domain и выполните
   на хосте: `ngrok http 8090`. Для явного использования этого домена добавьте
   `--url https://<ваш-домен>.ngrok-free.app`.
4. В Dashboard ngrok проверьте, что запросы доходят до нужного endpoint. Логи API
   должны содержать `429` для превышенных лимитов, но не реальные IP-адреса.

## Настройка реакции

Значения в `.env` можно менять без изменения исходного кода:

```dotenv
RATE_LIMIT_GLOBAL_PER_MINUTE=120
RATE_LIMIT_SEARCH_PER_MINUTE=60
RATE_LIMIT_SENSITIVE_ANON_PER_HOUR=3
RATE_LIMIT_CREATE_LISTING_PER_HOUR=10
```

После изменения примените их командой `docker compose up -d`. Для атаки, которая
создаёт много запросов с разных IP, этих лимитов недостаточно: бесплатный ngrok
не заменяет WAF/CAPTCHA. Не добавляйте CAPTCHA на чтение каталога; ставьте её только
на регистрацию, вход или создание объявления, если начнётся целевая накрутка.
